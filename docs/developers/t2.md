# The T2 developer command

## What T2 is and is not

T2 runs one system over the 10 public lives, both branches, with live probe answers and scripted write turns, compaction, extraction and embeddings. Its card shows every item's result and life. It is the middle tier of the developer loop; it does not certify a system or predict the full tier. Compare cards after changing your memory system; the developer report is still #392 work.

## What you need

Use a source checkout, Python 3.14 and a virtual environment with the development dependencies installed, public T2 packs built and installed against the current pins, and the pinned Hermes checkout with its dependencies and `mcp` extra. The [Ring 0 guide](ring0.md#7-run-t1-as-a-merge-gate) describes pack installation; select T2 at build. Supply a separate private login home containing `auth.json` and an explicit send bound. Set these privately, without putting their values in output:

| Setting | Purpose |
|---|---|
| `BICENTENNIAL_SOL_TOKEN_URL` | Login custody refresh service. |
| `BICENTENNIAL_SOL_CLIENT_ID` | Refresh client identifier. |
| `BICENTENNIAL_SOL_BASE_URL` | Live model service for the Responses bridge. |

Plug-in systems also need their pinned source and any required staged model cache. T2 admits at least four and at most eight worker slots under the machine guard. Another live run using the same login account cannot overlap T2. Keep login material outside output, packs, cache and destructive sandbox slots.

## Run it

```sh
export PYTHONHASHSEED=0
bicentennial t2 --system hermes-native --pack-hash "<pack hash>" --out "<new dir>" --login-home "<login home>" --packs "<packs>" --max-sends 1000 --hermes "<hermes checkout>" --cache "<floor cache>"
```

Replace the placeholders and quote paths as needed. The send bound is an example, not a promised budget. The pinned model is `gpt-6.1-sol`, effort `medium`; floor probes also use live answers. The command uses the same niced re-exec and fixed sandbox slots as T2-lite; install `nice` and, on macOS, `taskpolicy`. Build public packs with `bicentennial build --tier T2 --out build/ring0`; use the installed pack's hash.

| T2 flag | Meaning |
|---|---|
| `--system` | Registered system name; give exactly one of `--system` and `--entry`. |
| `--entry` | Outside registry entry file; see the [entry guide](entry.md). |
| `--pack-hash` | Required installed pack index hash. |
| `--out` | Required new output directory. |
| `--login-home` | Required private login home. |
| `--packs` | Required installed public T2 pack directory. |
| `--max-sends` | Required non-negative send bound, including identity checks and retries. |
| `--hermes` | Pinned Hermes checkout. |
| `--plugin-source` | Pinned plug-in checkout when required. |
| `--model-cache` | Staged model cache when required. |
| `--cache` | Optional shared per-unit no-memory floor cache. |
| `--sandbox-slot` | Fixed sandbox slot, default 0. |
| `--turn-wait` | Turn wait in seconds, 0.5 through 3.0, default 3.0. |

## How a run ends

A complete run publishes its card and receipts together after verification and a credential scan. Ordinary scored failures remain on the card and keep their pre-probe store copies. Credential, spend or live stops wipe partial output and publish an INFRA receipt, custody and refusal. Other refusals publish only `refusal.json`. Checks before output creation leave no output. Unexpected failures publish `tool_failure` when cleanup succeeds. Refusal precedence and publication checks follow T2-lite.

## The outputs

A kept copy is a directory tree containing its bundle and captured surfaces and workspace, rather than one file. The item pointer in the card names this tree. All reached items' hashes and unreached failed items are recorded in the kept index; only eligible reached failures have copies.

### Complete

| File | Contents |
|---|---|
| `card.json` | Per-item T2 scores, life, branch, probe point, exclusions, broken controls, floor provenance and kept pointers. |
| `outcomes.json` | Full outcome rows keyed by life/branch/item_id. |
| `no_memory.json` | Every floor unit's outcomes, stop and served identity, whether cached or live. |
| `kept/index.json` | Every captured item's hashes, reached status, kept path and bytes; unreached failures have no copy. |
| `kept/<life>/<branch>/<item_id>/` | Failed scored item's pre-probe copy directory tree. |
| `system/<life>/<branch>/t2lite_probes.json` | System probe diagnostics. |
| `no_memory/<life>/<branch>/t2lite_probes.json` | Live floor probe diagnostics; absent for cached units. |
| `receipt.json` | Whole-run volatile receipt, including every executed unit and attempt. |
| `receipts/system.json` | System arm's own runs and unit rows. |
| `receipts/no_memory.json` | Floor's own runs and unit rows; still written with no runs when fully cached. It includes an empty system background row from the shared receipt helper. |
| `units.json` | Effective slots, admitted slots, receipt endpoints, executed receipt unit rows plus `slots`, `predicted_s`, `card_index`, `pre_probe_ms` and `keep_ms`, and RING0 §14.8 arm time. Remove each row's slots field and call calculate_arm_times with effective slots and the endpoints to recompute it. |
| `custody.json` | Login custody events. |
| `disclosures.json` | Identity check, each floor unit's cached/live reason, transforms, live holds and stop disclosures. |
| `spend.json` | Live send/spend guard accounting. |

The no-memory floor counts in no arm's time, whether it ran or came from the cache; its replay is reported beside the arms as `floor_replay_ms`. Each arm's units replay in admission order (largest predicted time first, ties in card order), so a fresh floor cannot change the replay order. Its units still share the run's slots, the live service and the machine, so they can change the arm's measured unit times. A unit's time includes its probe clones, the copy before each probe over every attempt (`pre_probe_ms`), scoring, and keeping failed items' copies with any wait for the keep lock (`keep_ms`).

`receipt.json`, `units.json` and both arm receipts carry one run end, stamped after the credential scan of the outputs; only writing and scanning those four files, publishing the floor-cache entries and renaming the receipt and card follow it.

Each floor entry is stored in the optional cache as `<key>.t2-floor.json`, outside the output tree. The key hashes the life pack tree, branch, model, effort, answer contract, harness hash, benchmark commit, probe mode and turn wait. It excludes system and slots. A cache hit is reused only after one live served-identity check matches it. Each live unit is cached only when every scored floor item was measured from a live answer, its identity is known and stable, and none is BLOCKED. Entries are written after the final output scan.

### Credential stop

| File | Contents |
|---|---|
| `refusal.json` | Stop code and optional detail. |
| `receipt.json` | INFRA_FAILURE receipt over the collected attempts. |
| `custody.json` | Drained custody and stop records. |

If any publication contains login material, `credential_scan` takes precedence and only the refusal remains.

## Exit codes

0 means complete, including BLOCKED rows without a latched stop. 3 means refusal, stop or invalid CLI usage. 70 means unexpected tool failure. A cleanup double fault can escape as exit 1 with partial files and no card.

## Limits

Live wall time and the 1 h per-arm budget have not yet been measured; slice 10 owns those measurements and the scaling probe. A kept copy is a sound starting state, not an exact replay, until the restored-probe test passes (D6). Rows in `kept/index.json` carry run-specific digests; byte identity across live runs is not promised. Card pointers and kept identities do not depend on incidental session ids or finish order. G2 actions are not scored live until #118, whatever their failure class, and keep no copy; their hashes remain in the index. There is no developer report yet (#392), nor a reproduction command (#393). Entity matching is strict rather than semantic, and only probe answers are live.
