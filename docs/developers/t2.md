# The T2 developer command

See the [report guide](report.md) for file-based version comparisons and per-life differences.

## What T2 is and is not

T2 runs one system over the 10 public lives, both branches, with live probe answers and scripted write turns, compaction, extraction and embeddings. Its card shows every item's result and life. It is the middle tier of the developer loop; it does not certify a system or predict the full tier. Compare cards after changing your memory system; use the [developer report](report.md) to compare completed runs.

## What you need

Use a source checkout, Python 3.14 and a virtual environment with the development dependencies installed, public T2 packs built and installed against the current pins, and the pinned Hermes checkout with its dependencies and `mcp` extra. The [Ring 0 guide](ring0.md#7-run-t1-as-a-merge-gate) describes pack installation; select T2 at build. Supply a separate private login home containing `auth.json` and an explicit send bound. Set these privately, without putting their values in output:

| Setting | Purpose |
|---|---|
| `BICENTENNIAL_SOL_TOKEN_URL` | Login custody refresh service. |
| `BICENTENNIAL_SOL_CLIENT_ID` | Refresh client identifier. |
| `BICENTENNIAL_SOL_BASE_URL` | Live model service for the Responses bridge. |

Plug-in systems also need their pinned source and any required staged model cache. T2 admits at least four and at most eight worker slots under the machine guard. Another live run using the same login account cannot overlap T2. Keep login material outside output, packs, cache and destructive sandbox slots.

## Run it

```sh
export PYTHONHASHSEED=0
bicentennial t2 --system hermes-native --pack-hash "<pack hash>" --out "<new dir>" --login-home "<login home>" --packs "<packs>" --max-sends 1000 --hermes "<hermes checkout>" --cache "<floor cache>"
```

Replace the placeholders and quote paths as needed. The send bound is an example, not a promised budget. The pinned model is `gpt-6.1-sol`, effort `medium`; floor probes also use live answers. The command uses the same niced re-exec and fixed sandbox slots as T2-lite; install `nice` and, on macOS, `taskpolicy`. Build public packs with `bicentennial build --tier T2 --out build/ring0`; use the installed pack's hash.

| T2 flag | Meaning |
|---|---|
| `--system` | Registered system name; give exactly one of `--system` and `--entry`. |
| `--entry` | Outside registry entry file; see the [entry guide](entry.md). |
| `--pack-hash` | Required installed pack index hash. |
| `--out` | Required new output directory. |
| `--login-home` | Required private login home. |
| `--packs` | Required installed public T2 pack directory. |
| `--max-sends` | Required non-negative send bound for each arm's live sends, including retries. A system run spends it twice: first on the identity check and the live floor units, then afresh on the system units, so it makes at most 2 × N live sends. |
| `--hermes` | Pinned Hermes checkout. |
| `--plugin-source` | Pinned plug-in checkout when required. |
| `--model-cache` | Staged model cache when required. |
| `--cache` | Optional shared per-unit no-memory floor cache. |
| `--sandbox-slot` | Fixed sandbox slot, default 0. |
| `--turn-wait` | Turn wait in seconds, 0.5 through 3.0, default 3.0. |

## How a run ends

A complete run publishes its card and receipts together after verification and a credential scan. Ordinary scored failures remain on the card and keep their pre-probe store copies. Credential, spend or live stops wipe partial output and publish an INFRA receipt, custody, a stop record and refusal. Other refusals publish only `refusal.json`. Checks before output creation leave no output. Unexpected failures publish `tool_failure` when cleanup succeeds. Refusal precedence and publication checks follow T2-lite.

In a live run, a repository the reader's own edits leave unreadable is scored as the reader's failed task, never rerun. A G1 action probe records each such item with the diagnostic label `unreadable_state`; `disclosures.json` counts the items scored this way per arm under that key, over the scored attempt of each unit (an attempt voided by a harness fault is not counted). The item's decision table scores a changed repository with every predicate false. Harness faults still rerun the whole unit; scripted probes retain their infrastructure class. A file the reader makes unreadable by changing its permissions or by a symlink loop is still classed as infrastructure, because the same errors come from harness faults (#526).

## The outputs

A kept copy is a directory tree containing its bundle and captured surfaces and workspace, rather than one file. The item pointer in the card names this tree. All reached items' hashes and unreached failed items are recorded in the kept index; only eligible reached failures have copies.

### Complete

| File | Contents |
|---|---|
| `card.json` | Per-item T2 scores, life, branch, probe point, exclusions, broken controls, floor provenance and kept pointers. |
| `outcomes.json` | Full outcome rows keyed by life/branch/item_id. |
| `no_memory.json` | Every floor unit's outcomes, stop and served identity, whether cached or live. |
| `kept/index.json` | Every captured item's hashes, reached status, kept path and bytes; unreached failures have no copy. |
| `kept/<life>/<branch>/<item_id>/` | Failed scored item's pre-probe copy directory tree. |
| `system/<life>/<branch>/t2lite_probes.json` | System probe diagnostics. |
| `no_memory/<life>/<branch>/t2lite_probes.json` | Live floor probe diagnostics; absent for cached units. |
| `receipt.json` | Whole-run volatile receipt, including every executed unit and attempt. |
| `receipts/system.json` | System arm's own runs and unit rows. |
| `receipts/no_memory.json` | Floor's own runs and unit rows; still written with no runs when fully cached. It includes an empty system background row from the shared receipt helper. |
| `units.json` | Effective slots, admitted slots, wall receipt endpoints (`start_ms`, `end_ms`), executed receipt unit rows plus `slots`, `predicted_s`, `card_index`, `pre_probe_ms`, `keep_ms`, `t_start_ms` and `t_end_ms`, and RING0 §14.8 arm time. The unit offsets and top-level `t_end_ms` are monotonic nanoseconds minus the run's monotonic start, floored to whole milliseconds; arm time comes from these offsets. Inside `arm_time`, `start_ms`, `end_ms` and each timing's `start_ms` and `end_ms` are these offsets, with the run starting at 0; the top-level and unit-row `start_ms` and `end_ms` are wall-clock epoch milliseconds. The monotonic clock stops while the machine is suspended, so a sleep during a run counts toward no arm time; the wall stamps still include it. Recompute with `calculate_arm_times(*units_json_inputs(json.loads(...)))`, importing both functions from `bicentennial.runner.arm_time`. A backward wall-clock step larger than the run's elapsed time still fails the receipt's existing check, and the run publishes nothing. |
| `custody.json` | Login custody events. |
| `disclosures.json` | Identity check, each floor unit's cached/live reason, transforms, live holds and stop disclosures. `unreadable_state` counts, per arm, the items scored as the reader's failed task because its edits left the repository unreadable (an arm with no run, such as a fully cached floor, has no key). On a system run, `live` also holds `max_sends` and `phase_sends` (`floor`: the identity check and live floor units; `system`: the system units). The system phase's cap was `phase_sends.floor` plus `max_sends`. |
| `spend.json` | Live send/spend guard accounting. |

The no-memory floor counts in no arm's time, whether it ran or came from the cache; its replay is reported beside the arms as `floor_replay_ms`. Each arm's units replay in admission order (largest predicted time first, ties in card order), so a fresh floor cannot change the replay order. A live floor runs before any system unit starts, each with its own `--max-sends`, so it shares only the machine with the arm's units, not their slots or the live service. A unit's time includes its probe clones, the copy before each probe over every attempt (`pre_probe_ms`), scoring, and keeping failed items' copies with any wait for the keep lock (`keep_ms`).

`receipt.json`, `units.json` and both arm receipts carry one run end, stamped after the credential scan of the outputs; only writing and scanning those four files, publishing the floor-cache entries and renaming the receipt and card follow it.

Each floor entry is stored in the optional cache as `<key>.t2-floor.json`, outside the output tree. The key hashes the life pack tree, branch, model, effort, answer contract, harness hash, benchmark commit, probe mode and turn wait. It excludes system and slots. A cache hit is reused only after one live served-identity check matches it. Each live unit is cached only when every scored floor item was measured from a live answer, its identity is known and stable, and none is BLOCKED. Entries are written after the final output scan.

### Credential stop

| File | Contents |
|---|---|
| `refusal.json` | Stop code and optional detail. |
| `receipt.json` | INFRA_FAILURE receipt over the collected attempts. |
| `custody.json` | Drained custody and stop records. |
| `attempts.json` | Each collected attempt's sent tries, re-sends, refused tries, last send and first refusal times, INFRA labels from the run and from scoring, stop and audit status; the identity check's tries; totals (`max_sends`, the cap in force, its phase, the stack's sends, the unattributed remainder); and `cap_reached_in`: on a spend stop, the attempt with the latest send (two sends in the same millisecond tie, and the later attempt in card order is named); otherwise null. Times are the live stack's monotonic milliseconds. It holds no item ids, answers or served models, and is left out only if it cannot be built, so beside `credential_stop`, `spend_stop` or `live_stop` a missing `attempts.json` means exactly that. |

If any publication contains login material, `credential_scan` takes precedence and only the refusal remains.

This table includes the inherited T1 preparation vocabulary, including shared install and compare codes, as the T2-lite guide does. It is an over-approximation of codes reachable in this profile. Codes exclusive to T2-lite's reference and rerun flags are omitted. System reasons can be sorted and comma-joined. `<dist>` names a dependency and `<tool>` a registered tool.

## Exit codes

0 means complete, including BLOCKED rows without a latched stop. 3 means refusal, stop or invalid CLI usage. 70 means unexpected tool failure. A cleanup double fault can escape as exit 1 with partial files and no card.

## Limits

The first measured arm, Hermes native at 8 slots in the runner's background band on a Mac with 4 efficiency cores, took 1.60 h against the 1 h per-arm budget ([result](../../results/v0.3-dev-tools/2026-11-04-t2-live-arm/READING.md)); the bar is re-planned before its declaration ([#478](https://github.com/electricsheephq/bicentennial/issues/478)), starting with slice 10's scaling probe at 4 slots. A kept copy is a sound starting state, not an exact replay, until the restored-probe test passes (D6). Rows in `kept/index.json` carry run-specific digests; byte identity across live runs is not promised. Card pointers and kept identities do not depend on incidental session ids or finish order. G2 actions are not scored live until #118, whatever their failure class, and keep no copy; their hashes remain in the index. The [developer report](report.md) compares completed runs; there is no reproduction command yet (#393). Entity matching is strict rather than semantic, and only probe answers are live.
