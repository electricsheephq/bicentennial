# Bicentennial roadmap

Bicentennial is its own product, with its own repository, releases and site. Its versions are independent of LCM-X's.

**What it is for.** Today's memory benchmarks mostly ask whether a stored fact can be found again. Bicentennial asks what long-lived agents will need next:
- whether an agent's memory survives a life inside its own harness: restarts, compactions, crashes, model swaps and long gaps;
- whether it changes what the agent *does*;
- whether it obeys what the agent was told to keep, forget and never do;
- whether it learns from the agent's own attempts.

Many cells are hard on purpose. Some test capabilities that no surveyed system documents yet, and carry the label "undocumented frontier". The label is display only and never decides whether a cell is required: the season-1 frontier cells are diagnostics because of where they sit (Learn, the erasure probes, attestation, the conditional Image board, and the Survive stage for standing rules after compaction and a swap), and a zero there is published like any other result. Difficulty is frozen from controls only, and no target is set on any system's scores. Every cell's developer pack offers rungs, so a developer can measure movement below the board's lever values before a cell's verdict changes.

## Now: tasks that can rank (re-planned 2026-11-12)

**Milestone 1 is published** ([the step-2 page](results/milestone-1/2026-11-11-separation-table/RESULT.md), [`results/milestone-1/`](results/milestone-1/README.md), [#494](https://github.com/electricsheephq/bicentennial/issues/494)). Nine live arms ran at one commit, read by a declaration written before the runs. Two of the three kinds of scored task fail the oracle test: a reader handed the needed evidence still fails them, so a score on them cannot be read as a memory result yet. Wake is the one candidate. Hermes native reproduced its earlier result pair for pair. Of the two optional rows, Holographic's attempt stopped at the run's budget of live reader calls and has no score, and OMEGA, run with its reranker off as registered ([#289](https://github.com/electricsheephq/bicentennial/issues/289)), nets 0 on every kind. Apart from the developer loop below, the paused developer tooling stays paused while the validity work runs.

**Validity: tasks that can rank, then a run that can support a claim.** In order; where it competes with the developer loop, validity goes first.
- **Measure before repairing.** The Drift templates fail with the evidence handed over in different ways. `drift-chain-fault-v1` fails as a task in every row that sees evidence ([#505](https://github.com/electricsheephq/bicentennial/issues/505)). On `drift-quote-v1` the oracle row's failures follow the wording of the later statement, and on `drift-config-v1` it fails only where the right action is to leave the setting alone. Outside the screen, none of the oracle row's quiz count answers (`recall-count-v1`) could be parsed, which the scorer counts as a confident wrong answer ([#506](https://github.com/electricsheephq/bicentennial/issues/506) covers both templates and the count question). Each mechanism is measured on a control-only diagnostic run on public lives that keeps the reader's actions, before any template changes.
- **Repair.** Repair and calibration decisions come from control rows only; no kind is promoted or dropped because of a real system's score. Where the fault is in the harness, it is fixed outside the frozen scoring code; otherwise the template gets a new version. Either way, the repaired kind goes through three oracle trials on fresh control-only lives, with a frozen task list, before any system runs on it (declaration §6); PREREG's frozen oracle filter keeps a bundle only if each of its items passes with only its evidence in at least 2 of the 3. A new version's predictions are written only after its scripted naive-retrieval report on the public lives has been read, because a task's prompt is also naive retrieval's query (validity round 1: on the same public lives, `drift-config`'s new prompt raised what naive retrieval finds from 0 of 10 tasks to 7 of 10).
- **Validity round 1** ([declaration](results/validity-1/DECLARATION.md)): new versions of `drift-chain-fault`, `drift-config`, `drift-quote` and `recall-count` that change only their prompts, from the measured mechanisms. Seven control arms (three of them oracle) run on ten fresh lives that only control rows ever see, with seeds drawn after the declaration merges and a task list frozen before the first arm. The count question is validated for its answer format only ([#512](https://github.com/electricsheephq/bicentennial/issues/512)). **Result (13 November, [page](results/validity-1/2026-11-13-control-trials/RESULT.md)):** on this pack, with the evidence handed over, the reader does all four (oracle 100 on each, no memory 0), so the three Drift templates are cleared and the count question's format is validated. Naive retrieval also scores 100 on all four on this pack, so none of them can show that memory beats retrieval there; the three cleared templates enter the follow-up as do-no-harm checks.
- **Validity round 2** ([plan](results/validity-2/PLAN.md)). Round 1's three Drift templates cannot show that memory beats retrieval, because naive retrieval also scored 100 on them. Round 2 looks for kinds of task on which a reader handed the evidence does well and every naive anchor does badly, from control rows only, in this order:
  1. build the three naive anchors that do not exist yet: BM25, a scripted grep and a recent window of T2's size, outside the code pins and hashed per report ([#531](https://github.com/electricsheephq/bicentennial/issues/531), [#532](https://github.com/electricsheephq/bicentennial/issues/532));
  2. commit a 20-life G1 screening set ([#533](https://github.com/electricsheephq/bicentennial/issues/533)), then screen harder versions of the Drift templates against the four anchors with the scripted reader, at no model cost, each version described on a card before its first report ([#534](https://github.com/electricsheephq/bicentennial/issues/534)); the plan's predictions for each lever were published before any report;
  3. a live oracle smoke drops any finalist that a reader handed the evidence still fails ([#535](https://github.com/electricsheephq/bicentennial/issues/535));
  4. round 2 itself: thirteen control arms on ten fresh lives that only control rows see, Wake included whatever the screen finds ([#536](https://github.com/electricsheephq/bicentennial/issues/536)). A kind is a ranking candidate when the oracle row clears it, the best anchor scores at most 35 on it, and no near-solved flag applies.
- **Then the fresh-seed follow-up** ([#394](https://github.com/electricsheephq/bicentennial/issues/394)), only if round 2 finds at least one ranking candidate. It runs exploratory, with Ring 1's seed rules but not its full contract, which is a later item, on 24 fresh lives in two packs, 12 of them with scored actions: the floor, the four anchors, the oracle row and Hermes native. It reads, life by life, how far the oracle row and Hermes native sit above each anchor on the ranking kinds, with every kind's table printed beside it. If round 2 finds no ranking candidate, the screen and round 2 are published and the plan is redone.

**Developer loop: a real ten-minute tier.** Measure and cut the time T1 spends outside its arms; run one system arm and the no-memory floor on four short public lives in parallel on one host; add a machine-readable attribution per task (stored, retained, retrieved, used) and the `bicentennial repro` command. Before any system's next T2 run, fix the send budget and the refusal record that left Holographic's Milestone 1 attempt without a score ([#507](https://github.com/electricsheephq/bicentennial/issues/507)).

**Governance.** The Scoring Veto Panel is filled by its frozen rule (C-18), without narrowing it. Until it exists, by this roadmap's own choice and stricter than PREREG's interim rule (DESIGN §14), which still governs every freeze: no freeze changes the scorer, a scoring rule, or a pre-registered bar or target. Quantities the frozen rules already say how to set from controls, such as PREREG §9's difficulty scalars, are set by those rules. Each declaration and result is published with an adversarial review by a model family other than its author's: interim scrutiny, not a substitute for the panel.

**Act in the v0.1 Kit.** T0 and T1 run with no model. Their Act results are the scripted reader's evidence-conditioned actions, executed and scored by the real action scorer. They are labelled "evidence-conditioned scripted action; not an Act judgement", because a scripted policy measures whether the evidence was available, not what a model does with it. The Act stage proper starts with the live tiers: for G1 in v0.2's T2-lite, and for G2 in v0.4, once its action predicates score a live action by meaning (`specs/ring0/RING0.md` §3; `docs/ERRATA-v2.2.md` E12, as amended by E16). At T2-lite a G1 action is the live model's decision over a store built from scripted write turns, and its card says which roles were live.

## How Bicentennial differs from other memory benchmarks
- **The [Agent Memory Leaderboard](https://agentmemoryleaderboard.ai/) (AML) is a competitor.** It runs Textual, Coding and Multimodal tracks:
  - systems expose Add and Search endpoints;
  - a fixed platform pipeline answers the questions;
  - results come in seasonal cycles, with separate open-source and commercial rankings.

  Bicentennial follows AML's conventions where they help entrants: a versioned evaluation contract, and a non-scored smoke run before any full run.
- **[DolphinBench](https://dolphinbench.ai/), built by Mem0, is a shipped benchmark that, like Bicentennial, scores what an agent does with its tools, not what it can recite.** As of 2026-11-03 it has 3 simulated users with about 500,000 tokens of user messages each and 600 public tool-using tests, measured on 13 setups of memory system × model × harness, with cost and latency. Before the tests, each setup's agent processes the dated history in order, with its normal memory-writing behaviour.
  - **Where it is ahead today:** a public launch with a measured model × harness × memory grid; history processed live by each setup's agent; dollar and latency figures; histories dated across several years. Bicentennial's live scoring of personal-assistant (G2) actions, its dollar figures and a second harness are not shipped yet.
  - **What both check:** that a test needs its history. DolphinBench runs each test twice with the history (both must pass) and twice without it (both must fail). Bicentennial's design filters each bundle that counts toward the headline before any agent runs it (DESIGN §5.2: literal copy, blind pass, oracle failure, shortcut pass); the pilot ships these filters for Ring 0. A fixed 20% sample, never in the headline, skips the blind-pass and shortcut filters (§5.3).
  - **Where the designs differ:**
    - the unit of replication: Bicentennial generates many lives and computes its statistics clustered by life; DolphinBench has 3 users;
    - held-out data: Bicentennial seals its full-tier lives and keys and carries a canary string; every DolphinBench test is public, with its checks;
    - extra actions: Bicentennial scores a confident false memory or a harmful extra action at −1; DolphinBench ignores a call that no check names;
    - screening: Bicentennial's blind filter panel excludes the pinned agent's family; DolphinBench screened its tests with a model that is also the agent in ranked setups, so its item pool was selected on that model's behaviour;
    - time: Bicentennial simulates the clock through each life; DolphinBench's dates are text on the messages;
    - span: Bicentennial's full-tier lives cover weeks of simulated time (3-26 weeks, provisional until the next PREREG version; ERRATA E5), so it makes no claim about gaps of years.
  - Like DolphinBench, Bicentennial is built beside a system it tests, LCM-X. The firewall rules are in the README.
- **The claim Bicentennial has to earn with results:** memory inside a real agent harness across a life, judged on actions, covering governance, with a fast diagnostic loop. To that end it:
  - runs the whole system inside a real agent harness, across a life;
  - injects compactions, crashes and swaps;
  - judges actions by their outcomes in the world;
  - tests governance: forgetting through derived copies, consent and revocation, standing rules;
  - returns a repro bundle for every public failure.
- **What we do not claim:** firstness, multimodal novelty, or a better score than any system before the results exist.

## The site and leaderboard
- **Generated from the results.** The site is static and built from the result cards in the public repository, so no score is ever typed by hand.
- **Pages:**
  - **Board:** per season, one results table. For each system:
    - the full stack identity of the row: memory × harness × model, plus the vision provider and spend;
    - the capability map, track rows × profiles, with cell verdicts (CLEAR, UNRESOLVED or FAIL), cause labels such as "unsupported", and the non-results N/A, N/A_READER and BLOCKED. Remember and Survive are shown as diagnostic stages; Act carries the certification. Flatten's row reads "not yet built";
    - certification on Act per declared profile, with its certification stability;
    - the per-item action accuracy beside the penalised score, and twin consistency;
    - the harmful-actions panel, which is also the violations panel;
    - the baselines of each profile (the no-memory floor, the oracle-evidence ceiling, the full-history oracle ceiling where it fits, and naive RAG) and the raw-archive marker column;
    - operating metrics: latency p50 and p95, added turn latency, store growth, time-to-correct, cost and wall time per run;
    - G1 task completion, beside the scores and outside the headline.

    The memory headline holds the reader and harness fixed. A small predeclared crossover panel shows other models and harnesses. Its rows render past turns in the pinned reader's voice, the same text for every model, and a model from the blind-filter panel's family is excluded from it. Systems whose CIs overlap are shown as tied bands, not as ranks.
  - **Stack view:** model-native memories, on a separately labelled view outside board eligibility. It follows the board's eligibility rules except the open-source rule, and each row is vendor-submitted with a disclosed configuration.
  - **Census:** the dated capability census, from public documentation only, and the "undocumented frontier" labels it puts on cells. The labels never change whether a cell is scored, required or included, and no system's results ever set them.
  - **Robustness:** the seasonal study's fault pass^q, Keep curve, swap comparator and replication family, and its Learn-chain and erasure diagnostics. Each result is labelled with the versions it covered.
  - **Method:** the design, the pre-registration versions with their hashes and changelogs, the firewall statement, and the tuning detector (LCM-X at its last release before the public generator).
  - **For developers:**
    - how to run the Ring 0 packs, the rungs and the fault finder on your own system, with loop time published per tier;
    - how rung results are read: per-rung paired deltas with an A/A′ band and the smallest detectable effect, and a pooled curve shift, never a "highest rung cleared";
    - Ring 1 and Ring 2, and what each returns;
    - the pack catalogue, the repro bundle format and its classes, and guarded autonomous loops.
  - **Contribute:** how to contribute an executable template over a synthetic world, with its validity evidence on controls. Admission never depends on any system failing; a failure reproducer may illustrate a template but never qualifies it. No raw transcripts, corpus text or personal data.
  - **Submit:** how a system joins the board. It needs an open-source, self-hostable system with a Hermes memory plug-in or a documented ingest and query API, and an equal configuration budget. Model-native memories join the stack view instead; model labs use the sealed slice (v1.x).
  - **Roadmap:** this page.
  - **Runs:** every scheduled run, published in order, with its result card and spend. Traces are downloadable for public lives only.
- **Board rules shown on the site:**
  - every system's latest version, never its best;
  - every scheduled run is published;
  - delta boards run only on a new GA, with the previous version re-run alongside;
  - certification is issued only on a sealed board at the pre-registered size: a season board, or a delta board when powered. A season cut below the powered size issues no certificate, and its results are still published;
  - no claim of rank without separation.
- **Gate:** the leaderboard is published only after the v1.0 board exists. Until then the site carries the method, the developer packs and the roadmap.

## Papers
- **The Bicentennial paper, in two steps.** Both are written only from published result cards.
  1. **A preprint after the pilot:** the design, the pre-registration and its versions, and the pilot's validity evidence (filters, audits, known-order ablations, the controls).
  2. **The full paper with the season-1 board:** adding the board, the robustness study and the measured dev-predicts-full chain.
- **Papers about memory systems evaluated on Bicentennial,** LCM-X's among them:
  - they cite only published, sealed board runs;
  - a paper by a system's own maintainers also reports independent benchmarks, so Bicentennial is never the only evidence for a system built alongside it;
  - an LCM-X paper discloses that LCM-X and the benchmark share maintainers. The firewall rules apply unchanged.

## Standing rules
- **Firewall:** the benchmark never advises on LCM-X internals. LCM-X runs under the same rules as every system, and its developers never see held-out seeds, templates or keys. LCM-X improves only through outputs every registered system gets on equal terms: the public packs, Ring 1 results, Ring 2 bits per organisation, and published cards. The benchmark session runs nothing on LCM-X beyond the scheduled runs every system gets.
- **Cell inventory:** frozen per release from the ability taxonomy and the track templates, never from any system's documentation or results. The census only annotates it.
- **Difficulty:** frozen from controls only. No target or veto is set on any system's results, and valid zeros are published.
- **Spend:** reported on every run.
